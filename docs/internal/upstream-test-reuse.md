## Concrete reusable tests

- **Questionnaire:** [native choices and horizontal item navigation](https://github.com/shadcn-ui/ui/blob/3d98900e9b73c45f035f8109e9d41ba6a51685e7/packages/react/src/questionnaire/questionnaire.browser.test.tsx) supply the interactions for `NativeChoiceKeyboard` and `ItemArrowNavigation` in `src/components/stories/forms/Questionnaire.stories.tsx`. They use this package's existing survey composition rather than duplicating upstream's React root and DOM-query harness. Assertions cover radio selection, checkbox focus without selection, freeform focus, submitted values, unanswered-item guards, and contextual item navigation.
- **MessageScroller:** [browser tests](https://github.com/shadcn-ui/ui/blob/3d98900e9b73c45f035f8109e9d41ba6a51685e7/packages/react/src/message-scroller/message-scroller.browser.test.tsx) cover prepended-history anchoring, growing content, user interruption, memoized rows, and StrictMode. Compare with existing MessageScroller stories and native tests before adding duplicates.
- **Tremor:** [date picker tests](https://github.com/tremorlabs/tremor/blob/ca4d588f47820ff3d514d37fa4ee08a4222dec11/src/components/DatePicker/datepicker.spec.ts) supply opening, dismissal, preset, and time-control checks; [select tests](https://github.com/tremorlabs/tremor/blob/ca4d588f47820ff3d514d37fa4ee08a4222dec11/src/components/Select/select.spec.ts) supply selection, grouping, and disabled-state checks; [tracker tests](https://github.com/tremorlabs/tremor/blob/ca4d588f47820ff3d514d37fa4ee08a4222dec11/src/components/Tracker/tracker.spec.ts) supply a hover-tooltip scenario. Prefer them when adopting the corresponding capability; existing primitives already cover much of this behavior.

## Adaptation procedure

1. Bring the component's licensed source, fixture data, and useful assertions together. Record the source revision and modifications in `THIRD_PARTY_NOTICES.md`, preserving the applicable copyright, license, and NOTICE requirements. Confirm imported helpers and dependencies are covered too.
2. Put rendered behavior in a typed Storybook story with a `play` function and the `test` tag. Preserve separate meaningful states instead of importing a second test runner.
3. Replace upstream's hardcoded Storybook address, manager interactions, and iframe navigation with `within(canvasElement)`. Query portal content through the story's owner document and scope to its named surface.
4. Reuse assertions about state, focus, values, callbacks, and rendered content. Replace brittle CSS selectors with accessible queries. Do not port raw class-string or configuration checks, unconditional waits, or assertion-free interactions.
5. Keep pure transforms as unit tests. Keep browser default actions in the native Vitest browser layer when Storybook's Testing Library input helpers cannot exercise them. Vitest's [native input API](https://vitest.dev/api/browser/interactivity) and Storybook's [interaction testing API](https://storybook.js.org/docs/writing-tests/interaction-testing) use different input mechanisms.
6. Run `just llm-docs` before direct Storybook/Vitest commands in a fresh worktree. Run the affected story file first, then `just fix` and `just check`. Runtime changes also require the repository's behavioral regression and coverage gates.

## Limits of the upstream suites

- Tremor's BarList tests named “to be clickable and return value” click without checking the callback payload. Preserve their setup, but add an observable value assertion when adopting that behavior. Some chart tests assert CSS classes, and the Tracker hover is not awaited; copying these unchanged would retain weaknesses.
- Mantine UI's axe helper disables `region` and `autocomplete-valid`. Do not copy those exclusions into this package. Its “renders correctly” tests only mount the example; they do not exercise the feature named by the component.
- shadcn's IME test dispatches a synthetic `KeyboardEvent`. It is not copied into browser interaction stories. Its number-input browser test verifies focus retention, but does not assert numeric stepping. A stepping test needs native keyboard input rather than treating Storybook's simulated arrow key as an OS/browser action.
- Responsive layouts, complete dashboard compositions, package density, theme, portal behavior, scrolling contracts, and reduced motion need validation against this package even when upstream component tests are available.
